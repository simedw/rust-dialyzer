# Dependency transport performance

The CLI loads catalogues, asks the compiler bridge for identity and a prepared bundle, imports a prior into Store, runs compiled_analysis and renders Report. Store owns dependency semantics; the compiler bridge owns transport. Tiny-app profiling finds a 111,419,523-byte JSON bundle, including 95,605,017 bytes of prior data. Contracts account for 76,769,052 bytes and summaries for 16,498,211 bytes. The measured encoder consumes 3.3–4.2 seconds, before file transfer, JSON parsing and prior parsing.

Two designs were considered inline. Compressing the JSON stream reduces file size but still constructs and encodes the repeated expanded type trees. Capturing native summary and contract records in the existing flat ErlangTerms arena removes repeated terms before encoding and lets the existing NativeTerm::from_arena and Contract::from_capture reconstruct the same semantic objects. The second design addresses the measured cause and reuses existing parsing authority.

Caller usage remains bridge.prepare_priors followed by compiled_analysis::analyze. ExportDependencies gains a compact production transport; Store::import recognizes its version and builds the same Artifact, then runs existing validation and import logic. Older fixture versions retain their existing path. No inference results for target modules are substituted, and no native inference is added.

Verification compares all raw warnings, named signatures and documentation with the preserved development binary on identical BEAM inputs and prior, followed by individual Elixir corpus cases. Timers remain opt-in on stderr. No new parallelism is justified by this trace yet.

The first complete compact transport run preserved tiny warnings/types/documentation and reduced median latency from 14.057 s to 9.986 s. It also increased pipeline time from about 0.55 s to 3–4 s. CallWorld::active_contract calls CaptureEnvironment::literal_roots, whose TermOrderArena::new scans every term in the supplied arena. Retaining the all-contracts transport arena in each Contract therefore made each lookup depend on the size of the entire prior. The successor importer copies each contract's reachable terms once, retaining a bounded private capture for later lookups. This preserves the existing contract representation while separating transport sharing from analysis ownership.

Second-step trace on case 308 measures about 1.97 seconds of term arena self-roundtrips in 6.44 seconds of compiler preparation. A global skip-verification environment flag would make the production contract depend on hidden configuration. A separate capture_terms function and the existing checked export_terms wrapper make the production path explicit while preserving verification callers. The second design is selected. The Rust transport parser continues validating the captured representation at its boundary. Verification compares complete outputs and independent imported records before accepting the change.

Third-step ownership review traces physical metadata to three uses. The compiler bridge exports a complete prior header on every analysis, but only the success-typing output writer reads it. The build and checked-operation writers read only implementation file paths from the bundle; the exported implementation source forms have no consumer. Rust already owns bounded physical snapshot reading and fingerprinting, and the shared CompletedPlt writer owns completed tables.

Two shapes were considered. A purpose enum could select analysis or persistence exports in every prepare call, but it would carry filesystem knowledge and policy through the compiler transport. Alternatively, remove physical-header/context exports from PreparedBundle, return implementation paths once with bridge identity, and read prior fields through SnapshotFile only at the output writer. The second shape restores the existing Rust persistence owner, removes duplicated representations and avoids per-operation flags. Core compilation, atom-layout capture, prior summary/contract export and physical native prior loading remain unchanged.

No task-linked chat, observability, error-tracking or analytics evidence was supplied. The rationale for the original duplicate export is unknown; the proposed ownership change is based on current consumers and measurements, not inferred author intent.

The development driver had an unsupported writer branch, and that branch was the sole consumer of the complete exported physical header. The final design deletes the branch and header/context exports, keeps implementation paths on CompilerBridge, and shares the Native rejection rule between CLI parsing and the public operation boundary. Build/add/remove/check retain their existing canonical persistence owner. No new SnapshotFile API or prepare-purpose flag is needed.

Identity-entry design for case313. Current CompilerBridge::production constructs a bridge, runs identity, then uses the same compiled_bundle script for prepare/inspect/empty/primitives. The digest binds the Rust executable, six helper files and seven installed Native modules, and each preparation rechecks it. A persistent worker could avoid a second VM startup, but introduces a request protocol, worker lifetime and stream ownership. A separate identity entry point can remove irrelevant module compilation while keeping process-per-request failure isolation. Select the smaller identity entry point first. CompilerIdentity owns both digest computation and implementation paths; compiler_identity_main dispatches identity only, while compiled_bundle requires the same owner for request verification. CompilerBridge owns both entry paths and chooses internally by operation. Every constructor supplies both paths; no probing for optional sibling scripts or hidden fallback. Verify digest equality against the old function on exactly the same files, mutation rejection, positive primitives/prepare, output parity and measured latency.

Case314 copier design. ReasonBuilder::copy delegates to copy_arena, which discovers reachable source IDs in a BTreeSet and remaps each child through a BTreeMap. Each copied contract uses only a small fraction of the large transport arena. A dense whole-source ID array per copy would repeat large allocation/clearing costs; restoring shared all-contract captures would repeat the earlier inference regression. Select sparse HashSet reachability plus sorted reachable IDs and a pre-sized HashMap remap. Sorting preserves the exact previous copy order and IDs; no map iteration controls emission. The working set remains bounded by reachable terms. Verify every Native arena root against the original copier and inspect the real CLI before acceptance. This is a performance change, so a semantic failing-before test is not expected; the appropriate check is exact differential output plus measured timings.

The first sparse copier preserves270545 Native roots and126 library tests, but its three-round untraced full-run median3.053s to3.039s is under1% and one pair regresses. Do not accept it as a demonstrated whole-run optimization. Successor ArenaCopier owns one sparse remap/discovery table and reusable work/reachable vectors for an immutable source slice. One-off copy_arena delegates to that same algorithm; contract import retains one copier across its batch. Pending entries represent discovered nodes, resolved entries hold destination IDs, and sorted emission preserves the original order. All outputs still own bounded private arenas. This removes duplicate scratch tables and repeated allocation without whole-source arrays or shared output state.

The reusable sparse copier is also excluded: despite exact all-root/batch copies,3314 records and5407 signatures, its three-round full median3.033s to3.016s is about0.5%. Keep the original copier. A smaller ownership defect is visible in Contract::from_capture: b.finish creates a fresh Arc, then arena.as_ref().clone duplicates its complete forms vector and strings. Arc::unwrap_or_clone can move out that uniquely owned arena while preserving the same owned ErlangTerms field and shared-case behavior. Test this one-line ownership change independently in perf-11.

Retain only the one-line forms ownership fix. Three untraced measured rounds preserve all warning/signature/Doc output and show a small noisy median3.146s to3.111s, about1.1%; do not claim a major speedup. Complete3314 imported records and5407 signatures remain byte-identical, and Root157 library tests pass after the same scoped change. The subsequent trace overlapped Root test compilation and is excluded from performance evidence. Sparse-copier alternatives remain rejected. Next work targets compiler bridge startup/preparation, which dominates full latency.
